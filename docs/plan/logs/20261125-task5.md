## Decisions

- [deviation] Plan text said a heading is "`#` followed by a space or the line end" and
  "leading spaces ignored". The code (Task 2) takes 1 to 6 `#` followed by a space, tab or
  the line end, and ignores leading spaces and tabs (`trimStart()`); a closing fence may have
  spaces or tabs before and after. `SPEC.md` and the plan now say what the code does.
  Checked in Deno: `#\thttps://…` stays, `####### https://…` and `#tag https://…` move.
- [deviation] Unclosed frontmatter returns `links: 0`, `changed: false`; written into the
  plan's "Note sort".
- [deviation] The "✅ Sorted *n* links" count is `result.links`, all link lines in the note,
  also those that did not move; written into the plan's "Command" section and `SPEC.md`.
- [decision] Pop-up table in `SPEC.md` uses placeholders *n* and *note* (note name without
  `.md`, i.e. `file.basename`), like the existing add table uses *link*; the fixed text
  around them matches `src/main.ts` exactly.
- [decision] The "Sorting links" section sits after "Appending rules and notifications",
  because both describe what the plugin does to a note; it says adding never sorts.
- [decision] The reading-view limit is written as "hidden or does nothing; not yet checked in
  a real vault", because the manual check (Post-Completion) has not been done.
- [decision] Only the README feature list got a line. The README "Use" command table and the
  "Development" path table (no `src/sort.ts`, `tests/sort_test.ts` rows) were not changed,
  because the task lists only the feature-list line and the user rule forbids other doc
  changes. Left as an open item.
- [decision] The SPEC "Edge cases", "Overview → Scope" and "Technical notes" sections were not
  changed for the same reason; the sort's own edge cases and its editor write are in the new
  "Sorting links" section.
- [decision] The Before/After example in `SPEC.md` is a two-column table (one line per row)
  so the moved lines are easy to compare.
