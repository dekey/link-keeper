# Task 3: `ssh -G --` in the release script

- Plan: [docs/plan/done/link-sort-blocks.md](../done/link-sort-blocks.md)
- Date: 2026-11-26 (log name keeps the plan's `20261125-blk-t3.md`)

## What was asked

Task 3 of the plan (PR #2 review fix): in `scripts/release.sh`, `github_repo` must call
`ssh -G -- "${BASH_REMATCH[1]}"`, so a host from the origin URL that starts with `-` is read
as a host name, not as an ssh option. Check it with `bash -n` and two `ssh -G` calls, and
never run the real `gh`.

## What changed

- `scripts/release.sh` — `github_repo`: `ssh -G "${BASH_REMATCH[1]}"` →
  `ssh -G -- "${BASH_REMATCH[1]}"`, plus a one-line comment above it:
  `"--": a host that starts with "-" is a host name, not an ssh option.`
  Nothing else in the script changed.

## Decisions

- Added a one-line comment above the call. Without it a later edit could drop the `--` as
  noise; the rest of the script also explains each check in a comment.
- The check of `github_repo` ran on a copy of only that function (cut out with `sed` into
  `/tmp/blk-t3-scratch/github_repo.sh`), so no `gh`, `git ls-remote` or `make` line of the
  script could run.

## Checks run

- `bash -n scripts/release.sh` — pass (exit 0).
- `ssh -G -- github.com` — prints `hostname github.com` (exit 0).
- `ssh -G -- '-oHostname=x'` — prints `hostname contains invalid characters`, exit 255.
  With `--`, ssh reads `-oHostname=x` as a host name and refuses it.
- Without `--` (old form, for contrast): `ssh -G '-oHostname=x'` reads it as the option `-o`
  and prints the ssh usage text (no host left), exit 255.
- `github_repo` from the scratch copy (`bash /tmp/blk-t3-scratch/run.sh`):

  | origin URL | result |
  | --- | --- |
  | `git@-oHostname=x:owner/repo.git` | nothing |
  | `git@-oHostname=github.com:owner/repo.git` | nothing |
  | `git@github.com:owner/repo.git` | `owner/repo` |
  | `https://github.com/owner/repo.git` | `owner/repo` |
  | `git@gitlab.com:owner/repo.git` | nothing |

  So a host that starts with `-` gives no repository, and `release.sh` stops with "origin
  (...) is not a GitHub repository".
- Break on purpose: with the `--` taken out, `github_repo` still prints nothing for these
  hosts, because `-G` gets one argument only and no host is left after ssh reads the option.
  The difference shows only in how ssh reads the argument (option vs host name, see above).
  So the fix is a guard, not a change in result; no automated test covers the script
  (the project has no shell tests).
- The real `gh` and `scripts/release.sh` were not run.
- `shellcheck` is not installed here, so it was not run.
- `make test` — pass: 120 passed, 0 failed.
- `make lint` — pass (9 files).
