# Review fix: small smells in the sort code and tests

- Plan: docs/plan/link-sort-blocks.md (plain text, no link: the plan moves to

## What was asked

- Verify and fix 3 minor review findings (phase 2). Style fixes only: behaviour must not change
  and every test keeps its expected result. No commit. Do not touch the owner's `Makefile`
  change or the release/zip text.

## What changed (files)

- `src/sort.ts`: the list-marker pattern `(?:[-*+]|\d+[.)])[ \t]+` was written twice (the
  `marker` group of `LINK_LINE_RE` and `LIST_MARKERS_RE`). Now one `LIST_MARKER` string, and
  both regexes are built from it, so rule 1 (link line) and rule 5 (fence after list markers)
  always use the same list markers. Same regexes as before (source and flags compared with a
  scratch script).
- `tests/links_test.ts`: two test names now name the rule, in the same words as the others:
  "web link that is the second web address in the note is a duplicate" and "web link with a
  capital-letter scheme in the note is a duplicate".
- `tests/sort_test.ts`: the Windows line ending test for `lineChanges` used note links
  (`[[Zeta]]`), left over from the removed note-link sort. Now it uses web link lines
  (`- https://x.com/zeta` / `- https://x.com/alpha`); ends of the changes are ch 20 and 21.

## Decisions

- All 3 findings confirmed, none discarded.
- `LIST_MARKER` sits above `LINK_LINE_RE` with a short comment that names both users.
- Old task logs that say `LIST_MARKERS_RE` is a plain regex literal (`20261125-blk-t2.md`)
  are history and stay as they are.
