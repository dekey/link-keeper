# Task 1: URL pattern without a shared `g` flag

- Plan: [docs/plan/done/link-sort-blocks.md](../done/link-sort-blocks.md)
- Date: 2026-11-26 (log name keeps the plan's `20261125-blk-t1.md`)

## What was asked

Task 1 of the plan (PR #2 review fix): export `URL_RE` without the `g` flag, keep a private
global copy for `containsLink`, let `src/sort.ts` use `URL_RE` directly (drop
`FIRST_URL_RE`), add a test that `containsLink` finds the second web address in a note,
delete the `lastIndex` test and the `URL_RE` import in `tests/sort_test.ts`, and break the
rule once on purpose.

## What changed

- `src/links.ts`
  - `URL_RE` now has only the `i` flag. New comment: one `exec` finds one link and no
    position is kept, so any code can share it.
  - New private `ALL_URLS_RE` = `URL_RE` with the `g` flag added (built from
    `URL_RE.source` and `URL_RE.flags`), read only with `match`. `containsLink` uses it.
- `src/sort.ts` — removed `FIRST_URL_RE` and its comment; `firstWebLink` calls
  `URL_RE.exec` directly. No behaviour change.
- `tests/links_test.ts` — new test "containsLink finds the link when it is the second web
  address in the note": `"- https://a.com/x\n- https://b.com/y\n"` with `https://b.com/y`
  gives `true`.
- `tests/sort_test.ts` — removed the `URL_RE` import and the test "a position left in the
  shared link pattern does not hide the link of a line" (the shared pattern keeps no
  position now). The comment of the test "each line is read on its own…" now says the sort
  key reads the line with `URL_RE`, which has no `g` flag.

## Decisions

- The private copy is built from `URL_RE.source` and `URL_RE.flags + "g"`, so the pattern
  and the `i` flag live in one place only.
- The test "each line is read on its own: a long link line before does not hide the next
  link" stays: it still guards that `URL_RE` has no `g` flag (with `g`, the second `exec`
  would start after the first line and miss the link). Task 2 rewrites the key tests.
- The code-intelligence index does not list module constants (`URL_RE` not found), so
  `grep` was used to find every use: `src/links.ts`, `src/sort.ts`, `tests/sort_test.ts`.
  `src/main.ts` does not use it. No doc (`SPEC.md`, `README.md`, `AGENTS.md`) names it.
