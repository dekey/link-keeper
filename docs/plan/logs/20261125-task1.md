# Task 1: Sort key for one line

- Plan: [docs/plan/done/link-sort.md](../done/link-sort.md)
- Date: 2026-11-25

## What was asked

Task 1 of the plan: export `URL_RE` and `TRAILING_PUNCTUATION` from `src/links.ts`, add
`sortKey(line)` in a new `src/sort.ts` (no Obsidian imports, steps in the plan's exact order,
`URL_RE` read only through `matchAll`), and test every row of the "Sort key" table plus the
edge cases (no link → `null`, broken `%` code, shared-regex trap).

## What changed

- `src/links.ts` — `URL_RE` and `TRAILING_PUNCTUATION` are now exported. Added a comment on
  `URL_RE`: it has the `g` flag, so read it only with `match` / `matchAll`. No behaviour change.
- `src/sort.ts` (new) — `sortKey(line): string | null`. Picks the link that starts first in
  the line (web link via `line.matchAll(URL_RE).next().value`, note link via
  `/\[\[([^\]]+)\]\]/`, no `g` flag).
  - Web link: cut trailing `. , ; : ! ?`, cut from the first `?` or `#`, drop trailing
    slashes, take the text after the last `/`, decode `%` codes (keep the text if decoding
    fails).
  - Note link: cut the alias (from `|`), use the part before `#` (or the heading text after
    `#` when the part before is empty), take the text after the last `/`.
- `tests/sort_test.ts` (new) — 21 tests: 15 for the table rows, 4 for lines with no link,
  1 for a broken `%` code, 1 for the shared-regex trap.

## Decisions

- Comment added on `URL_RE` about the `g` flag, because it is now shared with `src/sort.ts`.
- Note links: no `%` decoding and no trimming of spaces, because the plan's note-link steps do
  not list them. For `[[#A#B]]` the key is the text after the first `#` (`A#B`), then step 3
  (text after the last `/`) still applies, as the plan says.
- Which link is first: compare the start positions of the first web match and the first note
  match; a missing match counts as "never", so the other one wins.
- One `Deno.test` per table row, named after the rule (for example "Markdown link is sorted by
  its address, not by its title, and keeps capitals"), each with an exact expected key.
- The code-intelligence index does not list module constants, so `grep` was used to confirm
  `URL_RE` and `TRAILING_PUNCTUATION` were used only inside `src/links.ts` before exporting.
