## Confirmed and fixed

1. Table end (`src/sort.ts`, `blockEnd`): a table ran to the next blank line, so a list,
   heading, quote, code block or comment right under a table (no blank line) was swallowed
   and never sorted. Reproduced: `| a | b |` / `|---|---|` / `| x | y |` / zeta / alpha gave
   `links: 0, changed: false`, and so did the "## Links" case and the table inside a list
   item. Now the table ends before the first line after the divider that is blank or starts
   another block (list marker, heading, `>`, fence, comment opener). The divider itself always
   belongs to the table, also when it starts with `- ` (as in `- | -`). Tests: list under a
   table, plain link lines under a heading under a table, code block / `%%` / `<!--` under a
   table, list item after a table inside a list item, divider that starts with `- `.
2. HTML comment close (`src/sort.ts`, new `closesHtmlComment`): a `--> <!--` line closed the
   comment although a new one opens on it. Reproduced: `alpha` moved into the comment and the
   commented-out `inside2` moved out. Now a line closes the comment only when it holds `-->`
   and does not open a new comment after it. Test with a `--> <!--` line.
3. Underlined headings (`src/sort.ts`, new `underlinedHeadingLines`): `[[Zeta]]` / `===` /
   `- [[Alpha]]` became `- [[Alpha]]` / `===` / `[[Zeta]]`. Now a run of text lines (not
   blank, not a list item or other block start) with a `===` or `---` line right under it never
   moves. A heading written over two lines keeps both lines. A `---` under a list item or a
   blank line is a divider. The "only `#` headings" known limit is removed from SPEC.md and
   the plan. Tests: `===` and `---` heading, two-line heading, `---` under a list item and
   under a blank line.

Small items from the reviewer:

4. Byte order mark moving with a first-line link line: fixed (trivial and safe). The mark is
   set aside before the split and put back in front, so it stays at the start; the
   frontmatter check no longer needs its own `replace`. Test.
5. Closing fence indented by 4 or more spaces: known limit (a real fix needs the list item's
   indent, which is not trivial).
6. `$$` math blocks and `<div>` HTML blocks: known limit (`$$` also shows up in plain text like
   `$$$`; HTML blocks end at a blank line; neither is trivial).
7. `<!-- %% -->` freezes the rest of the note: the existing inline-code known limit is widened
   to "inside the other kind of comment". A correct fix needs a left-to-right scan of both
   comment kinds (`%% <!-- %% -->` breaks a simple strip), so it is not trivial.

## Decisions

- [decision] Table stop lines are the same block starts the main loop knows (list marker,
  heading, `>`, fence, comment opener), shared with the heading check in `startsBlock`, so the
  comment pairing stays in step.
- [decision] Any list marker ends a table (also `2. `), as the reviewer proposed, to keep the
  rule simple; a table row without `|` at the start that begins like `2. text` ends the table.
  This is written into the SPEC table rule.
- [decision] A horizontal rule (`***`, `---`) does not end a table: a `---` under a table row
  is unclear in Obsidian, and keeping the lines in the table is the safe side.
- [decision] Underlined headings cover all text lines above the underline (multi-line
  heading), not only the last one, because Markdown and Obsidian make the whole paragraph the
  heading; found in one pass from the end so long notes stay fast (20000 plain link lines:
  72 ms).
- [decision] The quote stop for tables has no test: it only changes lines right under a
  quote without `>`, which Markdown counts as part of the quote. Added as a known limit
  instead of writing a test that locks in that behaviour.
