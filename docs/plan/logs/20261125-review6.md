## What changed (files)

- `src/sort.ts`
  - New `MARKDOWN_LINK_RE` and `firstWebLink`. When the first web address is in the title of
    a Markdown link `[…](address)`, the address in brackets gives the key, and the link starts
    at its `[`. `sortKey` uses it.
  - New `LIST_MARKERS_RE` (one or more list markers).
    - `openingFence` skips all markers (`- 1. ```).
    - `itemTextColumn` counts all of them.
  - `blockEnd`, fence: a fence opened after a list marker also ends before the first non-blank
    line indented less than the item's text column (that line is not in the block).
  - `textLines`: keeps the column where the paragraph starts (first line's indent, or the
    list item's text column). A block-start-looking line indented 4+ columns past it, right
    under the paragraph, counts as text. The numbered-line rule is unchanged.
- `tests/sort_test.ts`: 4 new tests:
  - a Markdown link with a web address in its title (4 lines);
  - a line indented 4+ under heading text (`    # cont`, `    - cont`, `    > cont`);
  - a fence after two markers (`- 1. ```, `- - ```, `1. - ```);
  - an unclosed fence in a list item ends with the item.
- `tests/acceptance_test.ts`: the cursor test "at the end of the last line" is renamed to say
  what it checks ("a cursor past the new end of a shortened link line …").
- `scripts/release.sh`
  - The CI Deno version is read without quotes, a leading `v` or a `#` comment.
  - New `github_repo`. An SSH host alias (`git@alias:owner/repo`) counts when `ssh -G alias`
    says `hostname github.com`. The URL as written is tried first, then
    `git remote get-url origin` (`insteadOf` short names).
  - `gh repo view "$repo" --json name` runs before `gh release view`, so a repository gh
    cannot see (where `release view` says "release not found") stops the script before the
    build.
- `SPEC.md`
  - "Sorting links": fenced code blocks (several markers, end with the item), the web link
    key (Markdown link title), the underlined heading rule (4+ columns).
  - "Known limits": a link line in a wrapped paragraph.
  - "Writing and messages": the editor scrolls to the cursor.
  - "Releases": origin forms and the repo access check.
- `README.md` Releases, `AGENTS.md`: the repo access check and the origin forms.
- `docs/plan/done/link-sort.md`: "Review fix 10" under "Changes made during implementation".

## Decisions

- [decision] Finding 4 (wrapped paragraph): listed in SPEC "Known limits", not fixed. Fixing it
  would freeze a link line whose neighbour is a text line. Then a common layout (an intro
  line right above a list of plain links) would silently stop sorting.
- [decision] Finding 9 (skip `setCursor` when the cursor's line did not change): no change.
  In the Obsidian app code both `transaction` (`scrollIntoView: true`, always) and
  `setSelection` (used by `setCursor`) scroll to the cursor. So leaving out `setCursor` would
  not stop the jump. SPEC now says the editor scrolls to the cursor after a sort.
- [decision] A code block opened after a list marker is closed by a closing fence at any
  indent, as before. Only lines that are not a closing fence end it at the item's end. So a
  closing fence at the left edge still closes the block, as users write it.
- [decision] An SSH alias is accepted only when `ssh -G` resolves it to `github.com`. Taking
  any `git@host:owner/repo` could send `gh --repo owner/repo` to the wrong GitHub repository
  when the alias points at another host.
- `.github/workflows/ci.yml` was changed by the user during this round: the top comment line
  is gone. Kept as it is.
- [deviation] `make zip` in CI: still not done (blocked by the auto mode classifier in review
  fix 7).
