## Confirmed and fixed

Major:

1. Cursor after the sort (`src/main.ts`): `setCursor(cursor)` reused the old `ch`. Obsidian
   1.15.1 (`Ri()` in the app code) counts `ch` from the line start and does not stop at the
   line end, so the cursor landed on a later line or the sort failed with a `RangeError` after
   the text was already written. Now `ch` is limited to the length of the cursor's line. The
   fake `setCursor` now works like Obsidian (lands on a later line, throws past the end) and
   the fake got `getLine`. Two acceptance tests: cursor at the end of a link line in the middle
   (stays on line 0, `ch` 21) and at the end of the last link line (no error, `ch` 20).
2. Comment blocks (`src/sort.ts`): `%%` and `<!-- -->` blocks now never move. A line with an
   odd number of `%%` opens or closes an Obsidian comment; a line where `<!--` starts and does
   not end opens an HTML comment, closed by the next line with `-->`. Tests: `%%` block, `%%`
   comment that starts after a link, one-line `%%…%%` still sorts, `<!--` block, one-line
   `<!-- -->` does not hide links below.
3. Code block on a list item line (```` - ``` ````, ```` 1. ``` ````): one list marker is
   skipped before the fence check. Test with both markers.
4. Tables without outer `|`: a line with `|` that has a divider line under it starts a table

## Decisions

- [decision] Cursor: limit `ch` with `getLine` after `setValue`, not `editor.transaction`,
  because it is the smallest fix and keeps the plan's `setValue` write.
- [decision] Comment blocks, list-item fences and tables without outer `|` are handled, not
  only documented: each can hide or show a link or break a table or code block, and each fix
  is a few lines.
- [decision] `%%` rule = odd number of `%%` in a line (not only a `%%` line), because Obsidian
  comments can start or end after text; a one-line `%%…%%` stays a normal line.
- [decision] A table runs from its header to the next blank line (not "while lines hold `|`"),
  because Markdown keeps rows without `|` in the table; this is fail safe (lines only stay).
- [decision] Byte order mark before frontmatter handled (one `replace`), because it is fail
  safe whether or not Obsidian keeps the mark in the editor text.
- [decision] Selection loss written into SPEC.md instead of rewriting the write with
  `editor.transaction`.
