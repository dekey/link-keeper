# Task 2: Sort the link lines of a note

- Plan: [docs/plan/done/link-sort.md](../done/link-sort.md)
- Date: 2026-11-25

## What was asked

Task 2 of the plan: add `compareKeys` (one `Intl.Collator("en", { numeric: true,
sensitivity: "base" })`) and `sortLinkLines(content)` to `src/sort.ts`, following the plan's
"Order" and "Note sort" sections (line ending per slot, frontmatter and fence rules, skipped
heading / table / quote lines, stable sort, write back into the link slots, return
`{ content, links, changed }`). Test the order pairs, the blocks and skipped lines, line
endings and small notes, each with the exact note text.

## What changed

- `src/sort.ts`
  - `compareKeys(a, b)`: one collator, made once; numbers by value, capitals and accents
    ignored.
  - `sortLinkLines(content)`: splits on `\n`, keeps each line's `\r` apart (the ending belongs
    to the slot), skips frontmatter (line 1 is exactly `---`, ends at `---` or `...`, never
    closed = whole note), skips fenced code blocks (3+ `` ` `` or `~`, closed only by the same
    character, at least as many, nothing else on the line), skips headings, table rows, quotes
    and callouts, finds link lines with `sortKey(...) !== null`, sorts them (stable) and puts
    them back into the link slots.
  - Small helpers, not exported: `openingFence`, `closesFence`, `isFixedLine`,
    `frontmatterEnd`.
- `tests/sort_test.ts` — 28 new tests (49 in the file now):
  - order: full key order list from the plan, capitals / accents equal, the Before/After
    example, digits before letters, numbers by value, capitals ignored, same key keeps old
    order, task line moves whole, note links and web links sort together, empty key `[[#]]`
    is still a link line;
  - blocks and skipped lines: frontmatter (LF and CRLF), frontmatter closed by `...`,
    unclosed frontmatter, `---` divider in the body, ```` ``` ```` block holding `~~~`,
    4-backtick block holding ```` ``` ````, fence line with text after it does not close,
    indented fence in a list item, unclosed fence runs to the end, heading / table / quote
    lines stay, indented callout stays, `#tag` line is not a heading;
  - line endings and small notes: CRLF note without a final line break, LF note without a
    final line break, empty note, one-link note, second sort changes nothing.
- `docs/plan/link-sort.md` — Task 2 boxes ticked.

## Decisions

- Heading = `#` to `######` followed by a space or the line end (Markdown heading rule). The
  plan's "`#` followed by a space" would miss `## [[Project X]]`, which the plan's own test
  expects to stay. A `#tag https://…` line is a link line.
- "Leading spaces ignored" uses `trimStart()` (spaces and tabs), for fences and for the
  heading / table / quote check. Closing fences use `trim()`, so spaces after the fence are
  allowed.
- Frontmatter lines are compared exactly (`---`, `...`), with no trimming, as the plan says.
- Unclosed frontmatter returns `links: 0` (no line outside the frontmatter, so no link line).
- Extra tests beyond the plan list, one per rule in "Note sort": `...` closes frontmatter, a
  fence line with text after it does not close, indented fence, unclosed fence, indented
  callout, `#tag` line, empty key `[[#]]`, and a direct `compareKeys` order test.
- Comment in `sortLinkLines` names `[[#]]` as the example of an empty key; checked in Deno that
  `[[#]]` and `[[|alias]]` give `""` (a web link like `https://a.com/?x` gives `a.com`, not
  `""`).
